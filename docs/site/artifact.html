MCP Design System — Agent Reference v1.2#

This folder is the machine-readable interface to the Design System v1.2. It is written for AI agents (Hermes and others) that generate, modify, or review dashboard UI code. Every file is self-contained and can be read independently.

What Is This?#

This DS is built on:

  • shadcn/ui — unstyled, accessible Radix UI components wrapped with Tailwind
  • Design System v1.2 tokens — a three-layer token architecture (Primitives → Semantic → Component)
  • Tailwind CSS — extended with DS-specific color, spacing, radius, shadow, and motion utilities

The design language matches the Gemini SaaS dashboard template: dark top bar, white sidebar, grey canvas, card-based content.

Token Architecture#

:root {
  /* PRIMITIVES (internal, _ prefix) */
  --_color-slate-900: #0f172a;

  /* SEMANTIC (use these in Tailwind) */
  --color-text-primary: var(--_color-slate-900);  → text-primary

  /* COMPONENT */
  --card-radius: var(--radius-card);              → rounded-card
}

Mode switching: Set data-appearance="light|dark" and data-brand="default|brand" on the root element. All tokens respond automatically. Never write dark: modifiers.

Design System v1.2 — Token Reference#

For agents: Always use semantic tokens (e.g., text-primary) in Tailwind classes. Never hardcode colors like text-slate-900 or hex values. The token architecture ensures automatic light/dark mode and brand switching.

Architecture#

Primitives (_color-slate-900)
    ↓
Semantic tokens (--color-text-primary → var(--_color-slate-900))
    ↓
Component tokens (--button-radius → var(--radius-control))
    ↓
Tailwind utilities (text-primary, bg-secondary, rounded-control)

Mode axes — applied via data attributes on a root element:

  • data-appearance="light" (default) | data-appearance="dark"
  • data-brand="default" (default) | data-brand="brand" (blue-accented)
  • data-density="default" (default) | data-density="compact"

Brand mode (blue accent)#

<html data-brand="brand">...</html>

Dark + Brand#

<html data-appearance="dark" data-brand="brand">...</html>

Agent rule: Place data-appearance and data-brand on <html> or the root layout wrapper. Never override individual token values inline — switch the mode attribute instead.

import { Button } from "@/components/ui/button";

  <Plus className="w-4 h-4" /> New Project
</Button>

// Secondary — paired with primary
<Button variant="secondary">Cancel</Button>

// Outline — filter bar actions, less emphasis
<Button variant="outline" size="sm">
  <Calendar className="w-4 h-4" /> Date Range
</Button>

// Ghost — nav items, icon actions in toolbars
<Button variant="ghost" size="icon">
  <Settings className="w-5 h-5" />
</Button>

// Destructive — delete/remove flows
<Button variant="destructive">Delete Account</Button>

// Link — inline text actions
<Button variant="link">Learn more</Button>

// Disabled state (works on all variants)
<Button variant="primary" disabled>Processing…</Button>

// asChild — render as another element (e.g., Link)
<Button asChild variant="primary">
  <a href="/dashboard">Go to Dashboard</a>
</Button>

Rules:

  • Use primary for the single most important action per view
  • Use outline or secondary for secondary actions
  • Icon buttons must use size="icon" — they become square
  • Never mix variant="primary" with Tailwind color overrides like bg-blue-600

Design System v1.2 — Dashboard Patterns#

These are the canonical composition patterns for building dashboard pages. Agents should treat these as blueprints — assemble from these blocks rather than inventing new layouts.

1. App Shell (Root Layout)#

The app shell is the full-screen container. It mirrors the Gemini template's structure: announcement banner → dark top bar → sidebar + main content.

// app/layout.tsx or root layout component
export default function AppShell({ children }: { children: React.ReactNode }) {
  return (
    <div data-appearance="light" className="flex flex-col h-screen overflow-hidden bg-canvas font-sans">

      {/* ── Announcement Banner (optional) ─────────── */}
      <AnnouncementBanner />

      {/* ── Top Navigation Bar ───────────────────────*/}
      <TopBar />

      {/* ── Body: Sidebar + Main ─────────────────────*/}
      <div className="flex flex-1 overflow-hidden">
        <Sidebar />
        <main className="flex-1 overflow-y-auto bg-sunken">
          {children}
        </main>
      </div>

    </div>
  );
}

Critical rules:

  • The root div carries data-appearance (not <html> in React) — this drives all token switching
  • h-screen overflow-hidden on root prevents double scrollbars
  • Only <main> scrolls — sidebar and topbar are sticky
  • Use bg-sunken on main (slightly grey background)

Full lint script source#

// scripts/lint-colors.mjs
import fs from "fs";
import path from "path";

const ROOT = new URL("../src", import.meta.url).pathname;
const SCAN_DIRS = ["app/(dashboard)", "app/(auth)", "components"];

const RULES = [
  { pattern: /(?:bg|text|border|ring)-\[#[0-9a-fA-F]+\]/g,
    message: "Hardcoded hex — use a DS token" },
  { pattern: /(?:bg|border|text)-\[rgba\(\s*79\s*,\s*70\s*,\s*229/g,
    message: "Hardcoded purple rgba — use bg-action-primary-subtle or bg-action-primary-tint" },
  { pattern: /text-slate-\d+/g,
    message: "Raw text-slate-* — use text-text-{primary|strong|secondary|subtle|muted|disabled}" },
  { pattern: /\bbg-white\b/g,
    message: "Raw bg-white — use bg-elevated" },
  { pattern: /\bbg-slate-\d+/g,
    message: "Raw bg-slate-* — use bg-surface-{sunken|elevated} or bg-bg-{secondary|tertiary}" },
  { pattern: /\bborder-slate-\d+/g,
    message: "Raw border-slate-* — use border-border-{subtle|default|hover|focus}" },
  { pattern: /(?:text|bg|border)-red-\d+/g,
    message: "Raw red-* — use {text|bg|border}-status-error-{fg|bg|border}" },
  { pattern: /(?:text|bg|border)-green-\d+/g,
    message: "Raw green-* — use {text|bg|border}-status-success-{fg|bg|border}" },
  { pattern: /(?:text|bg|border)-yellow-\d+/g,
    message: "Raw yellow-* — use {text|bg|border}-status-warning-{fg|bg|border}" },
  { pattern: /(?:text|bg|border)-blue-\d+/g,
    message: "Raw blue-* — use {text|bg|border}-status-info-{fg|bg|border}" },
  { pattern: /(?:text|bg)-orange-\d+/g,
    message: "Raw orange-* — use text-status-attention-fg" },
];

function* walkTsx(dir) {
  if (!fs.existsSync(dir)) return;
  for (const entry of fs.readdirSync(dir, { withFileTypes: true })) {
    const full = path.join(dir, entry.name);
    if (entry.isDirectory()) yield* walkTsx(full);
    else if (entry.name.endsWith(".tsx") || entry.name.endsWith(".ts")) yield full;
  }
}

let total = 0;
for (const scanDir of SCAN_DIRS) {
  for (const file of walkTsx(path.join(ROOT, scanDir))) {
    const rel = path.relative(path.join(ROOT, ".."), file);
    const lines = fs.readFileSync(file, "utf8").split("\n");
    for (const rule of RULES) {
      lines.forEach((line, i) => {
        rule.pattern.lastIndex = 0;
        const matches = line.match(new RegExp(rule.pattern.source, "g"));
        if (!matches) return;
        matches.forEach((match) => {
          console.error(`✗ ${rel}:${i + 1}  ${match}\n  → ${rule.message}\n`);
          total++;
        });
      });
    }
  }
}

if (total > 0) { console.error(`${total} violation(s).`); process.exit(1); }
else console.log("✓ No DS color violations.");

Adding a New Project#

To apply all 3 layers to a new project using this DS:

  1. Copy scripts/lint-colors.mjs (source above) into the project's scripts/ folder
  2. Add to package.json scripts:

``json "lint:colors": "node scripts/lint-colors.mjs", "lint": "next lint && node scripts/lint-colors.mjs" ``

  1. Create CLAUDE.md at project root using the template above
  2. Optionally add husky pre-commit hook (Layer 3)

That's it. The codebase is now enforced at write time (CLAUDE.md), at lint time (lint script), and at commit time (pre-commit hook).

Why This Exists#

Without enforcement, AI agents and developers gradually drift back to Tailwind primitives:

  • text-slate-600 is shorter to type than text-secondary
  • GitHub Copilot and similar tools suggest primitives by default
  • Copying code from Stack Overflow, shadcn docs, or AI outputs brings primitives in

The 3-layer system catches drift before it reaches the codebase. The CLAUDE.md stops it at generation time. The lint script catches it before merge. The pre-commit hook catches it at commit time.

All three are needed because each layer has gaps: an agent might not read CLAUDE.md carefully, a developer might skip lint, but a pre-commit hook cannot be bypassed without explicitly using --no-verify.

⚠️ Brand-Mode Token Override — REQUIRED#

data-brand="brand" on root enables indigo primary buttons but also changes --color-border-default → blue-200 and --color-surface-sunken → blue-50, making every input, card border, and outline button appear blue-tinted.

Always restore neutral tokens via inline CSS variables on the root element:

<div
  data-appearance="light"
  data-brand="brand"
  style={{
    "--color-surface-sunken":        "var(--_color-slate-100)", // neutral gray page bg
    "--color-border-default":        "var(--_color-slate-200)", // neutral input/card borders
    "--color-border-hover":          "var(--_color-slate-300)",
    "--color-action-ghost-bg-hover": "var(--_color-slate-100)", // neutral sidebar hover
    "--color-action-ghost-bg-active":"var(--_color-slate-200)",
    "--color-bg-secondary":          "var(--_color-slate-100)", // table header bg
    "--color-bg-tertiary":           "var(--_color-slate-200)",
  } as React.CSSProperties}
>

This keeps indigo for: primary buttons, active nav (bg-action-primary-subtle), focus rings, and links — while all neutral surfaces and borders remain slate gray.

The Golden Rules (never break these)#

  1. The template is the visual law. See TEMPLATE_STYLE.md. Full stop.
  1. Use semantic tokens only. Never use text-slate-900, bg-blue-50, or hex colors. Always use text-primary, bg-status-info-bg, etc.

→ See ENFORCEMENT.md for the full forbidden→correct mapping and the automated lint script that enforces this at build time.

  1. Never override component internals. Don't add raw Tailwind colors to <Button>, <Badge>, or <Card> to change their theme. Switch the variant instead.
  1. Import from @/components/ui/. All components live in ds-v2/src/components/ui/. If a component isn't there, check the index and use a composition.
  1. Use spacing tokens for gaps and padding. Replace gap-2, p-4, py-3 with gap-stack-sm, px-cont-px, py-stack-lg etc.
  1. Use Lucide icons everywhere. The DS is tuned for Lucide. Import from lucide-react. Never use feather-icons or inline SVGs.
  1. Respect layer order. Cards use bg-elevated, modal uses bg-overlay, page bg uses bg-sunken. Do not mix them.
  1. Dark mode is automatic. Never write dark: Tailwind modifiers. Apply data-appearance="dark" to the root and every token switches automatically.

Decision Tree — "What should I use?"#

I need to show data at a glance#

→ Stat card pattern → <Card className="p-5"> with text-2xl font-bold value + status color trend

I need to list records#

→ Data table pattern → <Table> inside <Card> with <CardContent className="p-0">, <Badge> for status, <DropdownMenu> for row actions

I need to organize page content into views#

→ Tabs pattern → <Tabs> + <TabsList> + <TabsTrigger> + <TabsContent>

I need a user to take an action#

→ Button → variant="primary" for the main CTA, variant="outline" for secondary, variant="ghost" for icon toolbar actions

I need to show state/status#

→ Badge → variant="success" | "warning" | "destructive" | "info" | "outline" → Never use custom color classes for status

I need a form field#

→ Input + Label + FormMessage → wrap with <Form> + <FormField> for validation

I need a confirmation / destructive action#

→ Dialog → <DialogContent> with <DialogFooter> containing <Button variant="outline">Cancel</Button> + <Button variant="destructive">Delete</Button>

I need a contextual menu on a row/item#

→ DropdownMenu triggered by <Button variant="ghost" size="icon"><MoreHorizontal /></Button>

I need to filter or narrow a view#

→ Select for single-choice filters, Button variant="outline" with <Calendar> icon for date ranges

I need a loading state#

→ Skeleton matching the shape of the real content

I need to inform the user of a condition#

→ Alert for persistent notices, Toast (via useToast) for transient feedback

I need to show no data#

→ Empty state pattern — icon + title + description + CTA button

Composing New Patterns#

When a task requires a UI element not explicitly in this guide, build it from primitives following this formula:

  1. Shell: Start with <Card> or a plain div with DS token classes
  2. Typography: Use text-primary / secondary / muted + text-sm/base/xl + font-medium/semibold/bold
  3. Spacing: Use gap-stack-* and gap-inline-* — never arbitrary pixel values
  4. Borders: Use border border-default — never border-gray-200
  5. Interactive states: Use hover:bg-action-ghost-hover and focus-visible:shadow-focus
  6. Status coloring: Use text-status-{error|success|warning|info}-fg and matching -bg / -border
