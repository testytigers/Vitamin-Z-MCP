# T0.1 · Run the audits in CI

**Status:** not started · **Tier:** 0 (gate) · **Cost:** ~15 min

## Why

The CI workflow runs `npm run build`, `npm run verify` and the smoke tests. It never runs
`npm run audit`. Every contrast rule, the CVD palette check, the layer contract and the
density contract are therefore unenforced on pull requests — a PR reintroducing every bug
the 2026-09-02 review fixed would merge green.

This is the highest-leverage change in the repository. Until it lands, none of the ~35
checks protect anything.

## What to change

- Add an `Audit` step to the workflow that runs `npm run audit`, after the existing verify
  step. `npm run audit` exits non-zero on any error, so no extra wiring is needed.
- Decide whether `npm test` should also include it, so a local run and CI agree. Recommended:
  yes — the split is why the gap went unnoticed.

## Acceptance criteria

- [ ] The workflow runs `npm run audit` on `push` to main and on every `pull_request`
- [ ] `npm test` and CI cover the same checks, or the difference is written down in this file
- [ ] A clean tree passes

## Verify

```bash
npm run audit && echo "audit clean"
```

## Prove it fails

Reintroduce one known defect, confirm the audit rejects it, then revert:

```bash
# text-placeholder in dark used to be slate-500 — 3.07:1 on the overlay surface
# swap it back, run the audit, expect a non-zero exit and an a11y error
npm run audit; echo "exit=$?"   # expect a11y errors and exit=1
```

- [ ] Confirmed the audit fails on a reintroduced defect **and** that CI goes red for it
      on a branch — a local failure alone does not prove the workflow is wired up
