# T1.2 · Automated accessibility assertions

**Status:** not started · **Tier:** 1 · **Cost:** ~1 day · **Depends on:** T1.1

## Why

`audit-full` check C5 verifies *labelling* statically. Nothing checks rendered
accessibility: not focus, not keyboard, not roles as the browser computes them. This is a
category no check in the repo currently touches at all, which is exactly why it is worth
doing — unlike most items here it cannot name a bug it would have caught, because nothing
has ever looked.

## Acceptance criteria

- [ ] `axe-core` runs over every component in all four mode combinations × both densities
- [ ] Every interactive component is asserted to show a visible focus indicator. The focus
      ring is composed from four tokens so it can be overridden; nothing currently verifies
      a component actually opts in
- [ ] Keyboard behaviour: tab order, `Escape`, and arrow keys on `select`, `menubar`,
      `navigation-menu` and `tabs`
- [ ] Focus trap **and** focus restoration on `dialog`, `drawer` and `sheet`
- [ ] `prefers-reduced-motion` is asserted to collapse motion. The token-level trick in the
      stylesheet disables every transition at once, which is elegant and completely untested
- [ ] Runs in CI

## Verify

```bash
npm run test:a11y
```

## Prove it fails

- [ ] Remove the focus-visible styling from `button.tsx`, confirm the focus-indicator
      assertion fails, then restore it
- [ ] Break the reduced-motion block in the stylesheet, confirm that assertion fails
