# T0.2 · Typecheck the design system

**Status:** blocked — needs the distribution decision below · **Tier:** 0 (gate) · **Cost:** ~half a day

## Why

The root `tsconfig.json` covers the MCP server only, so `npm run build` never touches the
design system. The 45 components have never been compiled by anything, in CI or locally.
Measured:

- 44 of 45 components import the `cn` helper from an alias path that does not resolve
  anywhere in this repo
- no `@/*` path alias is defined in any config here
- 0 of the 37 dependencies declared in the design system's own package manifest are
  installed in this tree

Every check that validates those components is regex over source text. A type error, a
wrong prop or a broken import passes silently.

They *do* all parse — `tsc --noResolve` over all 45 reports 0 syntax errors — so this is
absent verification, not known breakage.

## Blocked on one decision

Is the design system:

**(a) copy-in source** — the shadcn convention, where the consuming app supplies the `cn`
helper and the alias; or

**(b) a self-contained package** that ships its own helper and entry point?

Nothing in the repo records the intent. `CONTEXT.md` §1 notes the consuming app lives
outside this repository and has diverged, so it cannot be used as evidence either way.
Answer this first and write it into `COMPONENTS.md` — the answer changes everything below.

## Acceptance criteria

- [ ] The distribution model is decided and documented in `COMPONENTS.md`
- [ ] **If (a):** the peer requirements are documented — the helper, the alias, the
      dependency list — and the design system gets its own `tsconfig` that stubs the alias
      purely so CI can typecheck
- [ ] **If (b):** the `cn` helper ships in the design system, with a real `tsconfig` and an
      export entry point
- [ ] Dependencies install cleanly in the design system directory
- [ ] `tsc --noEmit` over the components passes, and runs in CI
- [ ] A check asserts the declared dependency list matches what the components actually
      import — an unused or missing dependency is silent today

## Verify

```bash
cd ds-shadcn && npx tsc --noEmit && echo "components typecheck"
```

## Prove it fails

- [ ] Introduce a deliberate type error in one component (pass a number where a string is
      required), confirm `tsc --noEmit` and CI both reject it, then revert
