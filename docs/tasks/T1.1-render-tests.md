# T1.1 · A test runner and render tests

**Status:** not started · **Tier:** 1 · **Cost:** ~1 day · **Depends on:** T0.2

## Why

There is no test runner in this repository — no vitest, jest, Testing Library, jsdom,
Playwright, axe or Storybook, and zero test files of any kind. No component has ever been
rendered by a machine or a human.

## Acceptance criteria

- [ ] vitest + Testing Library + jsdom (or happy-dom) installed and wired to a `test` script
- [ ] Every one of the 45 components: renders without throwing, forwards `ref`, applies an
      incoming `className`, and spreads unknown props onto the root element
- [ ] Every `cva` variant × size combination renders. Per `CONTEXT.md` §3 the variant map
      *is* the component contract, so this is the contract test
- [ ] Each component is imported in a server-rendered context and asserted not to throw
- [ ] Runs in CI

## Verify

```bash
npm run test:unit
```

## Prove it fails

The `"use client"` class of bug is the one to target, because it has already shipped twice:

- [ ] Remove the `"use client"` directive from `form.tsx`, confirm the server-render test
      fails, then restore it
- [ ] Confirm a variant test fails when a variant is deleted from a `cva` map

## Notes

`audit-components` has a `primitive-escape` and a `missing-use-client` rule, but both are
regex. The second one *already existed* and still missed three components, because it
enumerated six specific hooks. Rendering is what actually proves the contract.
